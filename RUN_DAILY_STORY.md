# Daily run (story format): one technical deep-dive reel

This procedure REPLACES the short-reel format in RUN_DAILY.md for new videos. Everything in RUN_DAILY.md that is not changed here still applies (setup, topic choice, research, hook/rehook/reach gates, facts file, reviewer pass, caption, delivery, log, results). Read STYLE_GUIDE.md first.

## Step 0 (new, owner analysis 6 Nov 2026): read CONTENT_STRATEGY.md completely and `results_log.md`
It sets the hook rules (concrete problem, number, contradiction or consequence; no generic intros), the experiment tag for today's run, the value test, the SEO caption rules, the topic pipeline and the extra deliverable `out/dayNN_brief.md` (its section 8).
Choose the shortest format that explains the mechanism accurately: if one idea fits in about 45 s use the short-reel procedure in RUN_DAILY.md; use the story format only when the mechanism really has several steps. Longer is not better.
Frame the topic as an interesting technical QUESTION or surprising failure ("Why does X happen / what can go wrong"), still answered with the real mechanism, numbers and trade-off from the sources. For AI topics start from a familiar user problem.

## What is different
| | old short reel | story format |
|---|---|---|
| audience | beginners | mature: knows the basics, wants to know what goes into building/running it |
| hook | claim or debate | promise of the mechanism with a number or concrete payoff (still hookscore 70+) |
| visuals | one scene per line, reset each time | `stage` scenes: persistent diagram, numbered step dots, typed terminal blocks, word-anchored timing |
| facts | one source is enough | at least 3 sources opened now (official docs first); every command, config, default or number is quoted verbatim in the facts file |
| length | 35-45 s | as short as the mechanism allows: 50 s if one mechanism fits, otherwise up to 150 s hard maximum; spec key `"format": "story"` (checker: 200-460 words, <= 2000 characters, 60-150 s) |
| music | ducked music | quiet music only; the owner mixes the voice |

## Steps
1. Setup and topic: as RUN_DAILY.md sections 0-1. Prefer topics that have a buildable pipeline (several steps, each with a real command or setting): RAG, CI/CD, caching, auth flows, queues, indexing, replication...
2. Research (section 2, stricter): open at least 3 sources now. Collect, with verbatim quotes, the real artefacts of each step: commands/queries/config, default values, limits, file formats, the official names of the steps. Pick ONE worked example and keep it identical everywhere. Note the single most important trade-off or failure mode with its source.
3. Script: 12-16 lines, one scene each. Structure: hook (promise + number) -> at most one line of why -> the named steps in one line (dots) -> for each step one or two lines of mechanism with the real artefact -> rehook (25-65%) answered by the payoff line -> catch (trade-off/failure) -> recap + "Follow for one tech topic a day.". Score hooks (6+ candidates, 70+) and rehooks (6+, 60+) as in RUN_DAILY.md section 3. Do not open with "Stop doing X"/a debate unless the whole topic is a comparison.
4. Spec: `specs/dayNN_slug.py` with `"format": "story"` and `stage` scenes. COPY THE STRUCTURE OF `specs/day11_rate_limiter.py` (layout grid, helpers `wi`, `TITLE`, `term`, `pkt`) and read the docstring at the top of `stage.py` for the object kinds. Design rules (STYLE_GUIDE.md, all enforced by the checker):
   - Build ONE main diagram in the first scene (y 540-940) from real objects: panels that CONTAIN things (`"in": parent`), stores with keys and values, servers, browsers, bars, grids, packets. Then change its STATE scene by scene (values, rows, highlights, focus/dim) instead of replacing it.
   - The lower area (y 975-1375) holds a terminal with real commands and real output from the sources (lines anchored with `"at"`), or a second diagram.
   - Labels 1-4 words, titles/questions at most 9 words, no sentences inside boxes. Every number on screen is sourced or listed as illustrative and labelled "Example".
   - Every object appears on its word (`wi(line, "word")`); something visible changes every 2-3 s; use `"focus"` to dim what is not being talked about.
   - Mascot `{"x": 1000, "y": 300, "size": 90}` (top-right next to the tag).
5. Facts file `specs/dayNN_facts.json` as before (terms, counts, rehook, share, replay, topic_terms, illustrative_numbers, claims with verbatim quotes, `length_reason`).
6. Build and check: `python3 build.py specs/dayNN_slug.py`, then `python3 check_spec.py specs/dayNN_slug.py --facts specs/dayNN_facts.json --video out/dayNN_slug_silent.mp4 --report out/dayNN_check.md` until 0 FAIL and 0 WARN. For stage scenes it also runs the LAYOUT CHECK (renders the stage every 0.25 s): TEXT_OVERFLOW (text that does not fit its box at 24 px or more), OVERLAP (objects colliding without nesting), OUTSIDE_PARENT, EMPTY_BOX, OUT_OF_ZONE, MASCOT_OVERLAP, TOO_MUCH_TEXT, STATIC. Fix the layout (shorter words, bigger boxes, nesting), never the checker. Run every test in `tests/`.
7. Look at it (mandatory, the checker cannot judge beauty): `python3 animsheet.py --step 2.0 --cols 6 specs/dayNN_slug.py out/dayNN_film` and read every strip. Look at full-size frames too (render 3-4 single frames with reel.frame(t) and Read them). Compare against STYLE_GUIDE.md and against the reference frames described there: does it look like the references (objects, nesting, state, little text)? text inside boxes, no overlaps, no dead screen, objects appear on their spoken word, nothing contradicts the voice, clean lettering, lower third calm.
8. Independent reviewer (fresh agent, files only, max 3 rounds until PASS): per sentence claim and quote; every example labelled; each visual appears at or after the word it illustrates (give it the `wi()` anchors); order on screen equals order of words; technical correctness of every command/number; rehook answered by payoff; each frame understandable alone. STOP RULE as before: no source quote or no PASS after 3 rounds -> deliver a problem list, not a video.
9. Caption, brief, sources, delivery, log, results: as RUN_DAILY.md sections 5-8, plus: the caption follows CONTENT_STRATEGY.md section 7 (main keyword in the first line, related terms where they add meaning, 3-5 hashtags, a save/send CTA tied to the "share" line), and write `out/dayNN_brief.md` (CONTENT_STRATEGY.md section 8: topic and audience, three alternative hooks with scores and a recommendation, storyboard with timing, exact on-screen text, visuals, transitions and purpose per scene, accuracy caveats, cover headline, caption, audio note, performance hypothesis with one validating metric, experiment tag). Send it with the other files. Put the experiment tag in the topics log "Hook angle" cell and the results rows. In the summary also state: script characters (voiceover credits), duration, and which steps carry a real command/number.
Never call ElevenLabs generation tools; never post anywhere.
